# 类别、课程目录与课程申请

管理员通过 `/admin/categories` 维护类别表：ID、名称、说明、是否允许半天。
INTERNAL、EXTERNAL、CERTIFICATION 由 CategoryDataLoader 在缺少时插入。
三条原始记录的名称和半天设置不能改变，也不能删除；说明可以修改。
新类别可以增删改，已被 Course 或申请使用的类别不能删除。

Course 保存名称、类别、培训机构、固定费用、介绍和可申请状态。
名称、类别、机构的组合唯一；同名但不同类别或机构是不同课程。
Course 是预先配置的完整课程库，页面不提供课程增删改。
CommonCourse 只关联已存在的 Course，管理员在 `/admin/common-courses` 页面上方查看常用目录，下方查看 All Course。
管理员通过 Add to Common 加入已有课程，通过 Remove from Common 移出；已加入的显示 Already Added。
关联具有唯一约束，服务端会拒绝重复加入。移出只删除 CommonCourse 记录，不停用或修改 Course，也不影响历史申请。
员工和经理共用 `/employee/courses`，同样按常用目录、全部课程上下展示，两部分共用搜索、类别和机构筛选。
员工和经理仅可查看详情和申请课程；页面没有课程编辑入口，后台管理操作拒绝非管理员访问。
所有角色的课程导航显示 All Course。旧课程新增/编辑页面跳转到目录页，旧写入接口不再提供。

员工和经理打开 `/employee/apply`，依次选择课程名、类别、培训机构。
名称下拉去重，类型和机构仅展示上一级选择中存在的选项，只有一个选项时自动选中。
所有新申请统一在 `/employee/apply` 页面填写及提交。课程目录只展示课程，点击 Apply 跳到同一申请页并固定课程名称、类别、机构和费用，不保存申请。
从侧栏直接进入申请页时仍可通过联动下拉选择课程；从课程链接进入时这些下拉只展示指定课程并禁用，日期、理由、半天与知识分享计划仍由申请人填写。
表单校验失败后保留指定课程与固定状态。
费用只读，提交和修改时服务器按 courseId 读取 Course 资料，忽略请求中的费用和机构文字。
员工填写日期、理由、知识分享计划，符合类别设置时可以选择半天。
页面仍使用原布局、配色、字段顺序和 CSS。

新申请保存 Course 关联和提交时的课程名、类别名称及费用，并关联培训机构表。
课程库维护不会自动改写已保存的课程名、类别名称及费用。机构改名后，已有申请的机构显示和搜索使用新名称。
编辑待审批申请时重新选择有效课程，使用该课程当前固定价格。
旧申请无法匹配课程时保留原记录，查看、审批、取消和完成仍正常，编辑时需要选课程。

半天须为允许半天的类别。起止日期可以相同，也可以覆盖多个工作日，最后一天计 0.5 天。
完整课程保持原有校验：结束日期必须晚于开始日期。起止日期须为工作日，开始日期须在未来。
trainingDays 在新建和修改时重新计算，排除周末和公共假日表中的日期。
没有主管不能申请；管理员不能申请；经理不能自审。

INTERNAL 新课程必须为零费用，不参与预算占用；其他类别的固定费用计入预算。
所有类别的培训天数计入天数额度。
APPLIED、UPDATED、APPROVED、COMPLETED 占用额度；其他三个状态释放额度。
修改申请排除本申请的旧记录，避免重复计算。修改年度上限仍不能低于已占用额度。

审批、通知、个人历史、Course view、月历、报表和额度 REST 查询沿用原来的流程。
类别搜索和经理报表的类别选项从类别表读取。

已有 MySQL 数据库按 `docs/course-selection-upgrade.md` 选择对应升级脚本。
新数据库由 Hibernate 建表，CourseDataLoader 初始化 18 条演示组合：6 个名称，每个名称 3 个类别。
INTERNAL 费用为零，其他类别费用以固定随机种子从 200、300、500 中选定。
初始化只在 Course 表为空时运行；常用目录不会自动填入演示课程，由管理员手动挑选。重启不会重新加入已移出的常用课程。
