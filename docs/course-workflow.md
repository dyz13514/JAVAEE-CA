# 类别、常用课程与课程申请

管理员通过 `/admin/categories` 维护类别表：ID、名称、说明、是否允许半天。
INTERNAL、EXTERNAL、CERTIFICATION 由 CategoryDataLoader 在缺少时插入。
三条原始记录的名称和半天设置不能改变，也不能删除；说明可以修改。
新类别可以增删改，已被常用课程或申请使用的类别不能删除。

常用课程通过 `/admin/common-courses` 维护，直接保存标题、类别、培训机构、参考费用、介绍。
它是管理员维护的目录，不是申请数量的统计。培训机构和公共假日仍使用原来的管理页面。
独立 Course 表、课程固定天数和可选排期已从程序删除。

员工和经理打开 `/employee/apply` 直接申请，自己填写日期、实际费用和理由。
也可以从 `/employee/courses` 浏览常用课程，点击 Use for Application 预填信息。
预填不保存申请，不要求固定开课日期，也不把申请绑定到目录记录。
之后修改或删除目录、修改机构名称，都不会改写申请中已保存的标题和机构文字。
类别仍关联类别表，因此修改自定义类别名称会同步影响已有申请的类别显示。

申请由服务器根据 categoryId 查找类别。半天须为允许半天的类别，并且起止日期相同。
完整课程保持原有校验：结束日期必须晚于开始日期。起止日期须为工作日，开始日期须在未来。
trainingDays 在新建和修改时重新计算，排除周末和公共假日表中的日期。
没有主管不能申请；管理员不能申请；经理不能自审。

INTERNAL 可以填写并保存非负实际费用，但不参与年度预算占用和超额校验。
其他类别的实际费用计入预算；所有类别的培训天数都计入天数额度。
APPLIED、UPDATED、APPROVED、COMPLETED 占用额度；其他三个状态释放额度。
修改申请排除本申请的旧记录，避免重复计算。修改年度上限仍不能低于已占用额度。

审批、通知、个人历史、Course view、月历、报表和额度 REST 查询沿用原来的流程。
类别搜索和经理报表的类别选项从类别表读取。

旧 MySQL 数据库需要先按 `docs/course-catalogue-upgrade.md` 迁移。
新数据库由 Hibernate 建表和 DataLoader 初始化。示例目录仅在首次建立演示员工时生成，
管理员后来删除的目录不会在重启后重新填回。
